# Release v3.0.0 — Explicit NONE Default

> Part of the RFC-0009 Rev 2 (Naming / View Configuration) release series.
> Companion to `CHANGELOG.md`; the CHANGELOG remains the canonical per-version list.

## Overview

`admin-core.explicit_none` flips from `false` to **`true`**: a related model with **no** human label column
(no `name`/`title`/`label` and no `displayColumn()` override) now renders as **NONE** — an empty cell — in a list,
show, or API relation label, instead of falling back to its route key (id / uuid).

- **Type:** Major
- **Breaking:** Yes
- **SemVer:** MAJOR — a default behavior change to a public display surface.

## Why this release exists

RFC-0009 Rev 2 classified "remove the silent route-key fallback → explicit none" as a MAJOR change to be delivered
**opt-in behind a compatibility flag, then flipped**. v2.87.0 introduced the flag (default off, deprecating the old
behavior); this release performs the planned flip so the correct behavior — a missing label is explicitly absent,
not a leaked identifier — becomes the default.

## Technical changes

- `config/admin-core.php`: `explicit_none` default `false → true`.
- `src/helpers.php`: `ac_related_label()`'s Explicit NONE gate now defaults on, so a label-less related model
  resolves to `null` (an empty cell) by default.
- The flag is retained as a **deprecated opt-out**: `ADMIN_CORE_EXPLICIT_NONE=false` (or `'explicit_none' => false`)
  restores the pre-v3.0.0 route-key display for migration. It will be removed in a future major
  (RFC-0009 Rev 2: "deprecate then remove").
- The change is display-only. `computed` labels (a `displayColumn()` accessor returning a real value), models with a
  real label column, the descriptor, `ac_display_column()`, `RelationDisplayColumn` semantics, search, and sort are
  all unchanged — the column facade still resolves a real fallback column, so nothing that queries by it breaks.

## Breaking changes

The displayed label of a **genuinely label-less related model** changes from its route key (id/uuid) to an empty
cell. Any relation whose model has a label column, and every `computed` label, is unaffected.

## Migration

Choose one:

| You want… | Do this |
|---|---|
| The new behavior (empty cell) | Nothing — it is the default. |
| Keep the old route-key display | Set `ADMIN_CORE_EXPLICIT_NONE=false` (deprecated opt-out, removed in a future major). |
| A real label instead of empty | Add a `name` / `title` / `label` column, or a `displayColumn()` method, to the related model. |

## Upgrade notes

`composer update`. Review any relation whose target model has no label column and whose id/uuid was intentionally
visible. See `UPGRADING.md` → v3.0.0 for the full decision table and scope.

## Testing summary

- `ExplicitNoneFlagTest` rewritten for the new default (NONE by default; the deprecated opt-out restores route key;
  `column` and `computed` labels unaffected in both states; the flip touches neither `ac_display_column`,
  `RelationDisplayColumn`, nor the descriptor).
- `DisplayLabelWiringTest` label-less assertion updated to the new default while asserting the column resolution is
  unchanged.
- Runs in the cross-database CI matrix.
