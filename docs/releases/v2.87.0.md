# Release v2.87.0 — Descriptor, View Configuration, Generator & Compatibility Flag

> Part of the RFC-0009 Rev 2 (Naming / View Configuration) release series.
> Companion to `CHANGELOG.md`; the CHANGELOG remains the canonical per-version list.

## Overview

Completes the Display Column / Model Naming subsystem (RFC-0009 Rev 2) as one coherent, additive, default-preserving
release: a structured display-column **descriptor**, the formalized resource **view configuration**, the runtime
read path and newly generated resources routed through them, and an **opt-in compatibility flag** for the future
Explicit NONE behavior.

- **Type:** Minor
- **Breaking:** No — every surface is byte-for-byte identical by default.
- **SemVer:** MINOR — additive; the opt-in flag defaults to off.

## Why this release exists

v2.86.2 fixed the fidelity defect, but the display-column resolution was still an implicit convention scattered
across consumers. This release formalizes it into named, immutable, resource-owned concepts so the framework has a
single, testable naming subsystem — and introduces the compatibility flag that lets products migrate to the future
Explicit NONE behavior on their own schedule.

## Technical changes

- **`ac_display_descriptor()`** — a new additive helper exposing a model type's display-column resolution as
  structured metadata: `['kind' => 'column'|'computed'|'none', 'column' => …, 'columns' => [...]]`. Resolves from
  the immutable class (composition fidelity), memoised per class, Octane-safe. (Backlog #4)
- **Descriptor is the single internal read source** — `ac_display_column()` is reimplemented as a thin string facade
  over the descriptor; `ac_related_label()`, and the `WebController` select/export label surfaces, read through it
  with no duplicated resolution logic. Byte-for-byte for every caller. (Backlog #5)
- **Resource View Configuration** — three immutable, stateless value objects under `Ngos\AdminCore\Support\View`:
  `RelationDisplayColumn` (the single column to display/sort/search one relation, or NONE for a computed/absent
  label), and the broad multi-column `SearchColumnSet` / `SortColumnSet`. `ApiController` search/sort,
  `WebController::select()`, and `ac_related_label()` read them; behavior is byte-for-byte. (Backlog #6)
- **Generator emission** — newly generated resources resolve a relation's search (`filterColumn`), sort
  (`orderColumn`), and filter-bar option label through `RelationDisplayColumn::for(...)->labelColumn()` (descriptor-
  backed, type-anchored, NONE-safe) instead of the inline helper. Generator output only; existing apps untouched.
  (Backlog #7)
- **Generator verification** — regression locks over the belongsTo / belongsToMany / self-referential emission,
  descriptor usage, deterministic/byte-stable output, and `php -l` validity. (Backlog #8)
- **Compatibility flag** — `admin-core.explicit_none` (default **false**). When off (default), a label-less related
  model still renders via its route-key fallback. When on (opt-in), it renders NONE. Gated in the label read path
  (`ac_related_label()`) only; a `computed` label is not gated; nothing else is touched. (Backlog #9)
- **Documentation** — CHANGELOG, UPGRADING, and README synchronized; developer notes for the descriptor and flag.
  (Backlog #11)

## Breaking changes

None. Public API signatures (`ac_display_column(): string`, `ac_related_label(): ?string`), rendered labels, search
matches, sort orders, exports, API responses, and existing generated applications are all unchanged by default.

## Migration

None required. To adopt Explicit NONE early (it becomes the default in v3.0.0), set
`ADMIN_CORE_EXPLICIT_NONE=true` or `'explicit_none' => true`.

## Upgrade notes

`composer update`. The descriptor, view configuration, and generator changes are internal — already-generated code
is unaffected, and newly generated resources behave identically. See `UPGRADING.md` → v2.87.0.
