# Release v3.0.1 — ErrorLogTest portability fix

> A follow-up PATCH. **Not part of the RFC-0009 Rev 2 program** (v2.86.1–v3.0.0) — a pre-existing test-portability
> fix. Companion to `CHANGELOG.md`.

## Overview

Makes the pre-existing `ErrorLogTest` case *"stores an ARGUMENT-FREE stack trace"* deterministic across PHP
runtimes by explicitly controlling `zend.exception_ignore_args` inside the test.

- **Type:** Patch
- **Breaking:** No
- **SemVer:** PATCH — test portability only; no runtime behavior change.

## Why this release exists

`Throwable::getTraceAsString()` inlines call arguments **only** when `zend.exception_ignore_args` is off (PHP's
development default). With it on — `php.ini-production`, and GitHub Actions' `setup-php` default — PHP strips
arguments from stack traces. The test's precondition, `expect($e->getTraceAsString())->toContain('SEKRETPASS')`,
therefore passed on a local dev machine but failed on CI. The defect was a non-portable assumption in the test, not
a production-code bug.

## Technical changes

- `tests/Feature/ErrorLogTest.php` — the affected test now reads and pins `zend.exception_ignore_args = 0` before the
  `throw` (the trace's arguments are captured at exception construction time), runs the two existing assertions, and
  restores the previous INI value in a `finally` block.
- **Both assertions are preserved**: the raw-trace sanity check (proves PHP *would* leak the argument) and the
  stored-trace security check (proves `ErrorLog::capture()` never stores it). Nothing is skipped, removed, or
  weakened.
