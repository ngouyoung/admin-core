# Release v2.86.2 — Composition Fidelity

> Part of the RFC-0009 Rev 2 (Naming / View Configuration) release series.
> Companion to `CHANGELOG.md`; the CHANGELOG remains the canonical per-version list.

## Overview

`ac_display_column()` now resolves a model's display column from the model's **immutable type** (a fresh instance
of the class, whose table is canonical and un-aliasable), never from a mutable runtime instance's `getTable()`.

- **Type:** Patch
- **Breaking:** No
- **SemVer:** PATCH — behavior is unchanged for correct cases; this fixes a crash / silent-wrong-column defect.

## Why this release exists

A relation-existence query — a self-referential `whereHas` on an adjacency-list relation (e.g. a category `parent`
or a lesson prerequisite) — calls `setTable('laravel_reserved_N')` on the related model to disambiguate the
self-join. `ac_display_column()` probed that **aliased** instance, so the `name`/`title`/`label` lookup silently
failed and fell back to the route key — and because the result was memoised per class, it **poisoned every later
call for that model in the process**. On PostgreSQL this surfaced as a hard error when the route key was a native
`uuid` column; on MySQL/SQLite it silently rendered and searched the wrong column. This is the root defect the whole
Naming / View Configuration program was built to fix correctly.

## Technical changes

- The schema is resolved from the type's canonical table (`(new $class)->getTable()`), which is immutable and
  cannot be aliased by a query.
- Resolution is therefore deterministic, the per-class memo is transparent (never poisoned), and the result is
  Octane-safe across resident-worker requests.
- The `displayColumn()` override, the `name → title → label` convention order, and the route-key fallback are all
  preserved unchanged.

> **Implementation note (Option A — subsume):** this fidelity fix was later refactored into the display-column
> descriptor introduced in v2.87.0 (Backlog #4). In the released source tree the fix lives inside
> `ac_display_descriptor()`; this version records the milestone at which the defect was closed. No behavior differs
> between the two forms.

## Breaking changes

None. No public API, generator, or configuration change; no migration required.

## Migration

None required.

## Upgrade notes

`composer update`. PostgreSQL applications using `uuid` route keys with self-referential relations stop erroring;
MySQL/SQLite applications stop rendering the wrong column for those relations. No consumer changes needed.

## Testing summary

- Added to the cross-database CI matrix.
