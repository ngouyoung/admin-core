# Release v3.0.2 — SidebarMenuLabelTest portability fix

> A follow-up PATCH. **Not part of the RFC-0009 Rev 2 program** (v2.86.1–v3.0.0) — a pre-existing test-portability
> fix. Companion to `CHANGELOG.md`.

## Overview

Makes the pre-existing `SidebarMenuLabelTest` deterministic on both case-sensitive (Linux/CI) and case-insensitive
(macOS/Windows) filesystems.

- **Type:** Patch
- **Breaking:** No
- **SemVer:** PATCH — test portability only; no runtime behavior change.

## Why this release exists

The test wrote its translation-group fixture only as `lang/en/courses.php` (lowercase) but exercises the collision
through `__('Courses')`. Laravel's `FileLoader` builds the group path **verbatim**
(`"{$path}/{$locale}/{$group}.php"`), so `__('Courses')` reads `lang/en/Courses.php`, whereas `ac_label('courses', …)`
reads `lang/en/courses.php`. A case-insensitive filesystem resolves both to one file (the test passed on macOS); a
case-sensitive filesystem does not, so `expect(__('Courses'))->toBeArray()` failed on CI ("Failed asserting that
'Courses' is of type array"). The defect was a non-portable test fixture, not a production-code bug.

## Exact Laravel behavior (verified)

`Illuminate\Translation\FileLoader::loadPaths()`:

```php
if ($this->files->exists($full = "{$path}/{$locale}/{$group}.php")) { … }
```

The group name is used verbatim (no lowercasing), confirmed by reading the source and by exercising the loader on a
real case-sensitive APFS volume:

- with only `courses.php`: `FileLoader::load('en', 'Courses')` → `[]` → `__('Courses')` is the string → fails.
- with both `Courses.php` and `courses.php`: `FileLoader::load('en', 'Courses')` → the array → passes; and
  `load('en', 'courses')` (for `ac_label`) still returns the array, unchanged.

## Technical changes

- `tests/Feature/SidebarMenuLabelTest.php` — the `ac_write_courses_lang()` helper now writes the group fixture at
  **both** filename cases (`lang/en/Courses.php` and `lang/en/courses.php`) and returns every path; each test deletes
  all of them in `finally`. All existing assertions are unchanged.

## Why this fix is preferable

- **Preserves the exact test.** The scenario (a Title-Case menu label `Courses` colliding with an FI-2 lowercase
  group file) and every assertion are kept; only the fixture is made available at the case the loader actually reads.
- **No production change.** Alternatives such as lowercasing the queried label would alter the tested scenario;
  changing production resolution is out of scope and unnecessary — the production guard (`ac_menu_label`) is already
  correct on every filesystem.
- **Deterministic everywhere.** On a case-insensitive FS the two writes are idempotent (one file); on a
  case-sensitive FS they are the two distinct files the two queries need.
